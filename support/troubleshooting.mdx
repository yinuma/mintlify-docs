Speclane Studio を使っていて動作が期待通りにならないとき、まず症状に合う項目を開いて手順を確認してください。問題が接続先にあるのか、ホストにあるのか、AI設定にあるのかを順番に切り分けることが解決への近道です。

<AccordionGroup>
  <Accordion title="取り込みたい過去のチャットが見つからない">
    インポート元の設定とセッション範囲を確認します。

    1. **「設定 → セッションのインポート」** を開き、履歴を保存しているマシンと元のAIの種類が正しく選ばれているか確認します。
    2. 「最近のセッション」の表示件数に上限がある場合、対象のセッションが範囲外になっている可能性があります。元のセッションIDを直接指定する方法を試してください。
    3. 取り込み済みの会話は自動的にスキップされます。「結果」タブと「会話一覧」を確認し、すでに存在するセッションとして扱われていないか見てください。

    詳しい手順は[取り込みの手順](/guides/import-sessions)を参照してください。
  </Accordion>

  <Accordion title="複製した会話で、元の作業にもファイル変更が見える">
    会話の複製（フォーク）はセッションの文脈のみを引き継ぎます。ファイルの編集場所は分離されません。

    1. 二つのセッションが同じ**作業ディレクトリ**を参照していないか確認します。
    2. 独立した検証や代替案を並行して進める場合は、**Git ワークツリー**などを使って作業フォルダを分けてから新しいセッションを開始してください。
    3. フォーク後に作業場所を変更するには、セッション設定の「作業ディレクトリ」を更新します。

    詳しくは[複製時の確認事項](/guides/fork-session)を参照してください。
  </Accordion>

  <Accordion title="共有した相手にファイルが見えない">
    閲覧権限のみの共有では、ワークスペースのファイルは相手に表示されません。

    1. 所有者が共有画面を開き、**「ワークスペースのファイル」** の共有オプションが有効になっているか確認します。
    2. 接続しているサーバーの設定によっては、共有範囲が管理者によって制限されている場合があります。管理者に確認してください。
    3. 共有先のユーザーが正しい接続先 URL にアクセスしているかも確認します。

    詳しくは[共有範囲を確認する](/guides/sharing)を参照してください。
  </Accordion>

  <Accordion title="Studioの画面が開かない">
    URL とネットワーク接続、サーバーの起動状態を順に確認します。

    1. 案内された URL に誤りがないかブラウザのアドレスバーで確認します。
    2. ネットワークに接続できているか確認します。
    3. ローカルで使っている場合は、ターミナルで `omnigent server status` を実行し、サーバーが `running` 状態か確認します。起動していなければ `omnigent start --server ''` で起動してください。
    4. `127.0.0.1` はブラウザを開いている端末自身を指します。**別のパソコンやスマートフォン**からアクセスするときは、管理者が案内する接続先 URL を使ってください。

    ローカル起動の手順は[ローカルで起動する](/support/local-start)にあります。
  </Accordion>

  <Accordion title="「ホストなし」「ホストがオフラインです」と表示される">
    作業を実行するマシン（ホスト）の状態を確認します。

    1. ホストとなるマシンの電源が入っており、ネットワークに接続されているか確認します。
    2. 再接続画面にコマンドが表示されている場合は、**そのホストの所有者**が対象マシン上でそのコマンドを実行します。
    3. 自分が所有していないホストがオフラインの場合は、ホストの所有者または管理者に再接続を依頼してください。
    4. 複数のホストがある場合は、オンラインのホストを選び直して作業を継続できます。
  </Accordion>

  <Accordion title="AIに「設定が必要」と表示される">
    選択したホスト上でそのAIのインストールまたはサインインが完了していません。

    1. 画面の案内に従い、AIのインストールとサインインを行います。操作権限がない場合は管理者に依頼します。
    2. すでに別のAIがホスト上で準備済みの場合は、セッション設定から別のAIに切り替えて作業を継続できます。
    3. インストール済みのAI一覧はホストの設定画面で確認できます。
  </Accordion>

  <Accordion title="仕様書やファイルが表示されない">
    ホストと作業フォルダの選択、およびプロジェクト設定を確認します。

    1. セッションで選択しているホストと作業ディレクトリが正しいか確認します。
    2. **「設計」タブ**は、対象の作業ディレクトリ内に Markdown ファイル（仕様書）が存在する場合にのみ表示されます。ファイルが存在しない場合はタブ自体が現れません。
    3. 通常のファイルは**「ファイル」タブ**から参照します。
    4. ホストがオフラインの場合はファイルを読み込めません。まずホストの接続状態を確認してください。
  </Accordion>

  <Accordion title="「反映」「確定（コミット）」ボタンを押せない">
    ボタンが無効になっている原因を順番に確認します。

    1. AIが現在処理中でないか確認します。処理中はボタンが無効になります。完了後に再試行してください。
    2. 操作対象の**未反映の変更**が存在するか確認します。変更がない状態では「反映」は押せません。
    3. そのセッションに**編集権限**があるか確認します。閲覧のみの権限では変更操作はできません。
    4. **「履歴（コミット）」** は Git 管理下の作業フォルダでのみ利用できます。Git が初期化されていないフォルダでは使用できません。
    5. ボタン付近に表示される案内メッセージを確認し、指示に従ってください。
  </Accordion>

  <Accordion title="操作を依頼したのに状態が変わらない">
    AIへの依頼が正しく送信・処理されているか確認します。

    1. チャット画面でメッセージを送信したあと、**「処理中」「承認待ち」「失敗」** のいずれかの状態が表示されているか確認します。
    2. 「OK」はAIへの依頼を送信するボタンです。クリックしたあとにチャットにメッセージが表示されているか確認してください。
    3. 変更が完了している場合は **「履歴を更新」** ボタンで最新状態を取得します。
    4. 検証に失敗した変更は未反映のまま残ります。チャットに報告された失敗の理由を解消してから再度依頼してください。
  </Accordion>

  <Accordion title="AIがコミットを実行できないと報告する">
    現行の Speclane-Skills では、AIによるコミット操作は禁止されています。

    1. 同じホスト・作業フォルダで、**利用者自身が Git ツール**（ターミナル、VS Code、GitHub Desktop など）を使ってコミットを実行します。
    2. 自分でコミット操作ができない場合は、そのリポジトリの担当者にコミットを依頼してください。
    3. 「確定」ボタンを使う場合の手順は[確定の標準手順](/guides/change-lifecycle#確認待ちの変更を確定する)を参照してください。
  </Accordion>

  <Accordion title="プッシュ・プルができない">
    GitHub連携とアクセス権、作業中の変更の状態を確認します。

    1. **「設定 → サンドボックス連携」** を開き、GitHub接続が有効になっているか確認します。
    2. 対象リポジトリへの**プッシュ・プル権限**があるか、GitHub側のリポジトリ設定で確認します。
    3. チャットに接続先やブランチについての質問が出ている場合は、回答してから再度操作してください。
    4. **プル**は、未整理の変更（コミットされていない変更）がある場合や、ローカルとリモートの履歴が分岐している場合に停止します。担当者と状況を確認し、作業中の変更を先に整理してからプルを再実行してください。
  </Accordion>

  <Accordion title="AIが停止・スリープしている">
    ホストの状態を確認してから、AIへの次の指示を送ります。

    1. まずホストが**オンライン**であることを確認します。オフラインの場合はホストを先に再接続してください。
    2. ホストがオンラインであれば、チャットに次の依頼を送ります。AIの復帰が始まったら、完了するまで待ちます。
    3. 長時間スリープしている場合は、セッションを一度閉じて開き直すと状態がリセットされることがあります。
  </Accordion>
</AccordionGroup>

## 担当者へ報告するときに伝える情報

上記の手順を試しても解決しない場合は、担当者または管理者に問い合わせてください。状況をすばやく把握できるよう、以下の情報をあらかじめ用意してから連絡してください。

| 項目 | 確認内容 |
| --- | --- |
| 発生日時 | 問題が起きた時刻（タイムゾーンも添えると確認しやすい） |
| 画面のエラー文 | エラーメッセージや警告の文言をそのままコピーする |
| 直前の操作 | 問題が発生する直前に行った操作の手順 |
| 接続先 URL | アクセスしていたサーバーの URL |
| ホストと作業場所 | 使用していたホスト名と作業ディレクトリのパス |
| ブラウザ・OS | ブラウザの種類とバージョン、OS の種類 |

<Warning>
  報告内容に認証トークン、APIキー、秘密鍵、パスワードなどの機密情報を含めないでください。担当者がこれらを要求することはありません。
</Warning>
