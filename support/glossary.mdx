Speclane Studio の画面や AI との会話には、製品固有の概念や Git・開発ワークフローに関する用語が多く登場します。操作中に意味が分からない言葉があったとき、このページを参照してください。仕様駆動開発の概念から Git の基本操作用語まで、Studio で使われる主要な用語をまとめています。

| 用語 | 意味 |
| --- | --- |
| 仕様駆動開発 | 期待する動作を仕様として共有し、その仕様を基準に実装と検証を進める開発方法。 |
| 正本仕様 | チームが判断の基準として使う仕様書。合意や変更を反映して継続的に維持する。 |
| 受入条件 | 機能が目的を満たしたと判断するための条件。仕様書に記載され、検証の基準になる。 |
| 受入シナリオ | 前提・操作・期待する結果を具体化した動作確認の単位。受入条件を実際の手順として表現したもの。 |
| 仕様ドリフト | 仕様書に書かれた動作と、実際の実装にずれが生じている状態。定期的な照合で検出する。 |
| Speclane-Skills | 対話・調査・仕様化・実装・検証などを進めるための、AI向け手順のまとまり。AIの行動を標準化する役割を持つ。 |
| セッション | AIとの一連の会話と、その作業の単位。画面ではチャットとして表示される。 |
| エージェント | 指示を受け、資料の確認やファイル編集などの作業を自律的に進めるAI。 |
| モデル | AIの判断や文章生成を担う仕組み。選べる種類は実行環境の設定に依存する。 |
| メタハーネス | 複数のAIエージェントの実行方式を共通の画面から利用するための基盤。仕様駆動開発を含む、さまざまな作業の共通基盤となる。 |
| ハーネス | AIを動かす実行方式。画面の設定やインポート元の分類に使われる（例：Claude Code、Codex など）。 |
| インポート | 別のAIツールの会話履歴を、Studioのセッションとして取り込む操作。 |
| 複製／フォーク | 会話の経緯を引き継いだ別のセッションを作ること。ファイルの分離には別途作業場所の指定が必要。 |
| ホスト | AIの作業を実際に実行するマシン。Studio の画面から接続して使う。 |
| サーバー | ブラウザやホストが接続するStudioの接続先。ローカルまたは組織の共有サーバーを使用する。 |
| 作業ディレクトリ／ワークスペース | そのセッションで作業するフォルダ。AIのファイル操作はここを基点に行われる。 |
| プロジェクト | 関連するセッションをまとめるための分類単位。 |
| 仕様書／Spec | 機能の目的、条件、期待する動作を記した資料。Markdownファイルとして管理されることが多い。 |
| リポジトリ | Gitでファイルや変更履歴を管理する単位。 |
| ブランチ | ほかの作業と変更の流れを分けるための枝。並行して複数の作業を進めるときに使う。 |
| ワークツリー | 別ブランチの作業を独立したフォルダで進めるGitの仕組み。フォーク後の作業分離にも活用できる。 |
| 差分 | 変更前と変更後のファイルの違い。Studio の画面ではレビュー画面に表示される。 |
| ステージング | 次に履歴へ記録する変更を選択済みの状態にすること。画面の「確認待ち」に対応する。 |
| コミット | 変更を説明文とともに履歴へ記録すること。画面の「確定」に対応する。現行の Speclane-Skills では利用者が Git ツールで実行する。 |
| コミットSHA | 履歴の特定の記録を識別するための文字列。変更の追跡やロールバックに使う。 |
| リモート | リポジトリの共有先（GitHub など）。チームメンバーとコードを共有するために使う。 |
| プッシュ | ローカルの確定済み変更をリモートリポジトリへ送ること。 |
| プル | リモートリポジトリの変更を現在の作業場所に取り込むこと。 |
| スキル | 特定の作業のために用意された手順や指示のまとまり。利用可否はAIと実行環境によって異なる。 |
| ランナー | セッションのAIを動かす実行プロセス。接続の案内やエラーメッセージに表示されることがある。 |
