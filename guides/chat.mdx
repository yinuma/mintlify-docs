AIへの依頼は、目的・対象・完了条件の3つを明示するだけで精度が大きく上がります。曖昧な指示を繰り返すより、最初の依頼で意図を揃えておくほうが作業全体を速く進められます。このページでは、依頼文の組み立て方から完了報告の確認まで、一連の流れを説明します。

## 目的・対象・完了条件を伝える

依頼には「何を実現したいか（目的）」「どこを変えるか（対象）」「何を確認できれば終わりか（完了条件）」の3要素を含めます。変更したくない点があれば、それも一緒に伝えましょう。

```text
目的：利用者が予約を取り消せるようにしたいです。
対象：予約一覧画面と、取消処理のロジック。
条件：予約日の前日まで取り消せること。当日は取り消せないこと。
完了条件：両方のケースを確認し、変更したファイルと結果を報告してください。
まず変更方針を説明してください。
```

<Tip>
  方針の確認を先に求めておくと、意図とずれた実装が進むのを防げます。「まず説明してください」の一文を依頼の末尾に加える習慣をつけましょう。
</Tip>

## 資料を渡す

### ファイルを添付する

メッセージのファイル添付操作、または入力欄へのドラッグ＆ドロップで資料を添付できます。どの部分を参考にしてほしいかも本文に書くと、意図がより正確に伝わります。

```text
添付した仕様書の「キャンセルポリシー」セクションを参照し、
取消処理の実装に反映してください。
```

### 作業フォルダ内のファイルを指定する

作業フォルダ内のファイルを指定する場合は、パスを直接テキストで伝えます。

```text
src/reservations/cancel.ts の現在の実装を確認し、
変更が必要な箇所を教えてください。
```

画面にファイルへのリンクが表示されたら、クリックして内容を確認できます。

### @メンションでファイルを選ぶ

対応するコーディングAIでは、入力欄で `@` を入力すると作業フォルダ内のファイルやフォルダを選択できます。

```text
@src/reservations/cancel.ts
上記ファイルのキャンセル判定ロジックを確認し、前日チェックの条件を追加してください。
```

<Note>
  特定の行を指定したい場合は、[ファイルの特定箇所にコメントを付けてAIへ修正を依頼する方法](/guides/review-comments)を参照してください。
</Note>

## 質問や承認が表示されたら

AIが選択肢や質問を示した場合は、目的に合う内容を選んで回答します。操作の承認では、対象のファイル・コマンド・アクセス先を確認してから判断してください。

<Warning>
  承認の選択肢と実行できる範囲は、AIの種類・権限モード・接続先の設定によって異なります。迷う場合は、必要な理由や影響をチャットで説明してもらってから判断しましょう。
</Warning>

<Tabs>
  <Tab title="質問への回答">
    AIから「どちらの方針にしますか？」といった質問が来たら、目的に照らして回答します。曖昧なまま進めると後から修正が必要になるため、不明点はここで解消しておきます。

    ```text
    前日チェックはサーバー時刻（UTC）を基準にしてください。
    タイムゾーン変換は不要です。
    ```
  </Tab>
  <Tab title="操作の承認">
    ファイルの書き込みやコマンドの実行などで承認を求められた場合は、対象を読んで影響範囲を確認してから「承認」または「拒否」を選びます。

    ```text
    対象ファイルと実行するコマンドを一覧で確認させてください。
    影響範囲を説明してから進めてください。
    ```
  </Tab>
</Tabs>

## 依頼を修正する

結果が意図と違った場合は、違う点と期待する結果を具体的に伝えます。

```text
会社名は必須ではなく任意です。
未入力でも送信できるように修正し、確認結果を報告してください。
```

実行中の作業を止めたい場合は、チャット入力欄の**停止ボタン**を使います。

<Warning>
  停止するまでにAIが行った編集はファイルに残ることがあります。停止後は「ファイル」タブと「履歴」で状態を確認してから次の依頼を送ってください。
</Warning>

## 完了報告を確認する

AIから完了の報告が届いたら、以下の点が含まれているかを確認します。

<CardGroup cols={3}>
  <Card title="変更ファイル" icon="file-pen">
    どのファイルが変わったか。変更の概要と理由が書かれているか。
  </Card>
  <Card title="確認結果" icon="circle-check">
    どんな確認を行い、何が成功したか。テストや動作確認の結果が含まれているか。
  </Card>
  <Card title="残作業" icon="list-check">
    未完了のことや、利用者による確認が必要な事項が明記されているか。
  </Card>
</CardGroup>

AIの報告を読んだら、実際の画面や変更差分でも内容を確認します。

<Note>
  仕様駆動開発として進めている場合は、[変更を反映・確定する](/guides/change-lifecycle)も参照してください。
</Note>

同じ経緯から別の提案も得たい場合は、[会話を複製して別案を並行検討する](/guides/fork-session)へ進みます。
