「履歴」パネルは、Gitで管理されている作業フォルダの変更状態を一元管理する場所です。作業中の変更から確定済みの記録まで、変更のライフサイクル全体をここで確認・操作できます。変更を確定する前に、[仕様と受入条件の合意](/guides/requirements-and-decisions)が済んでいることを確認してください。Speclane-Skills を利用している場合の担当手順は[スキルの役割](/guides/skills)を参照してください。

## 変更の3つの状態

変更を次の記録の候補に選ぶ操作を「ステージング」と呼び、Studio では「確認待ち」と表示されます。詳しい用語の定義は[用語集](/support/glossary)を参照してください。

| 画面の状態 | 意味 | 次に行うこと |
| --- | --- | --- |
| **未反映**（未ステージング） | 作業中の変更がある | 差分を確認して「反映」を依頼する |
| **確認待ち**（ステージング） | 履歴に記録する候補になっている | 差分と確認結果を読み、確定するか判断する |
| **確定**（コミット） | 変更が履歴に記録されている | 必要に応じてリモートに送信する |

<Note>
  状態表示は Git の状態に対応します。別のツールでステージングした変更も「確認待ち」に表示されます。状態名だけで検証済みとは判断せず、必ず差分と実行結果を確認してください。
</Note>

Speclane-Skills 利用時は、AI が実装・検証して確認待ちへ進め、利用者が差分と結果を確認して確定します。

## 確認待ちの変更を確定する

**確定（コミット）は、変更を説明文とともに Git の履歴へ記録することです。** 記録されるのは確認待ちの変更全体です。今回の作業より前から入っていた変更も含まれる場合があるため、内容全体を確認してから確定してください。

### 標準手順：利用者が Git で確定する（Speclane-Skills 環境）

現行の Speclane-Skills では、AI が実装・検証と確認待ちへの移行を担当し、**コミットは利用者が実行します。** Studio の「確定（コミット）」ボタンは AI へコミットを依頼する操作のため、この規約が適用される環境では、利用者自身が Git ツールで記録します。

<Steps>
  <Step title="確認待ちの変更を読む">
    「履歴」パネルの「確認待ち」セクションを開き、記録する変更全体と検証結果を確認します。今回の作業に関係しない変更が混在していないかも確かめてください。
  </Step>
  <Step title="Git クライアントまたはターミナルを開く">
    同じホスト・作業フォルダ・ブランチを、利用者が操作する Git クライアントまたはターミナルで開きます。ブラウザを開いているパソコンの別フォルダで実行しないよう確認してください。
  </Step>
  <Step title="差分を確認してコミットする">
    確認待ちの変更を確認し、内容を説明するメッセージを付けてコミットします。ターミナルを使う場合は次のコマンドを使用します。

    ```bash
    git status
    git diff --cached
    # 表示された記録対象を確認してから実行します。メッセージは実際の変更に合わせます。
    git commit -m "予約後の機器確認時間を追加"
    ```
  </Step>
  <Step title="履歴を更新して確認する">
    Studio で「履歴を更新」を押し、新しい記録と変更内容が正しく表示されていることを確認します。
  </Step>
</Steps>

<Info>
  Git クライアントでは「ステージ済み」が Studio の「確認待ち」に対応します。別の作業の変更が混在している場合は、先に対象を整理してからコミットしてください。AI が別のホストで作業していて自分で Git を操作できない場合は、そのホストを操作できるプロジェクト担当者へ確定を依頼します。
</Info>

### AI によるコミットが許可された環境の場合

Speclane-Skills のコミット禁止規約が適用されず、プロジェクトで AI によるコミットが許可されている場合は、Studio から直接依頼できます。

<Steps>
  <Step title="確認待ちの変更と検証結果を読む">
    確認待ちの変更全体と検証結果を読み、記録して問題ないことを確かめます。
  </Step>
  <Step title="確定ボタンを押す">
    「確定（コミット）」を押し、確認画面で「OK」を押します。キャンセルした場合は依頼は送られません。
  </Step>
  <Step title="コミット結果を確認する">
    AI が報告した説明文、コミットの識別子、変更概要を確認します。
  </Step>
  <Step title="履歴への追加を確認する">
    「履歴」に新しい記録が追加されていることを確認します。失敗や承認待ちの報告だけでは確定済みとは扱わないでください。
  </Step>
</Steps>

<Warning>
  この操作では確認待ちの変更のみが記録されます。未反映の変更の追加やリモートへの送信は含みません。「OK」を押すことでプロジェクトの禁止規約が解除されるわけではありません。
</Warning>

### 制限で確定できない場合

AI が規約や権限を理由に実行できないと報告した場合は、同じ依頼を繰り返さず、上の「利用者が Git で確定する」手順へ進みます。利用者自身にも権限がない場合は、ホスト・作業フォルダ・ブランチ・記録する差分・検証結果を担当者へ伝え、確定を依頼してください。

## 確定する前に見直す：未反映に戻す

確認待ちの変更をもう一度整理したい場合は、「未反映に戻す」を押します。確認後、**確認待ちの変更すべて**のステージングが解除されます。ファイルの編集内容は残ったまま未反映の状態に戻ります。

<Warning>
  「未反映に戻す」は過去の内容へ巻き戻す操作ではありません。ステージングが解除されるだけで、ファイルの変更内容は保持されます。戻した後も差分を確認してから次の操作を行ってください。
</Warning>

## リモートとやり取りする

コミット済みの変更を共有先と同期するには、リモートプッシュとリモートプルを使います。どちらの操作も「設定 → サンドボックス連携」での GitHub 接続が必要です。操作が利用できない場合は、画面の案内を確認してください。

<CardGroup cols={2}>
  <Card title="リモートプッシュ" icon="arrow-up">
    確定済みの変更を共有先（リモートリポジトリ）に送る操作です。確認後に AI へ依頼が送られ、結果はチャットに表示されます。送信先やブランチが不明な場合は、AI からの確認に答えてから進めます。
  </Card>
  <Card title="リモートプル" icon="arrow-down">
    共有先の新しい変更を取り込む操作です。未整理の変更がある場合や履歴が分岐している場合は、そのまま進めず理由を報告するよう指示されます。
  </Card>
</CardGroup>

<Tip>
  Studio から AI へ依頼する操作（確定・プッシュ・プルなど）は、確認画面で「OK」を押した時点で依頼が送られます。キャンセルした場合は送られません。送信後はチャットの進捗と完了報告を確認してください。
</Tip>

## デプロイはコミットとは別に確認する

「反映」「確定」「プッシュ」はそれぞれ異なる操作です。

- **反映**：仕様書とプログラムコードの同期
- **確定（コミット）**：変更を Git の履歴へ記録
- **プッシュ**：確定済みの変更をリモートへ送信

利用者が使う環境への公開（デプロイ）は、プロジェクトに設定された配布手順や CI/CD によって別途行われます。反映やコミットが完了しただけでは公開済みとは判断しないでください。公開が必要な場合は、対象の環境・配布結果・公開後の動作を別に確認してください。
