Speclane Studioの画面は大きく三つのエリアに分かれています。左側で会話やプロジェクトを選び、中央でAIに依頼し、右パネルで仕様書・ファイル・変更履歴・プレビューを確認します。また、AIが「どこで・何に対して」作業するかは、サーバー・ホスト・作業ディレクトリという三つの要素で決まります。このページを読んで、作業を始める前に画面構成を把握してください。

## 画面の見方

左サイドバーでは過去の会話一覧やプロジェクト設定を管理します。中央のチャットエリアでは指示・質問・承認のやり取りを行い、AIの進捗や回答を確認します。右パネルでは、その会話の作業場所に紐づいた情報を複数のタブで参照できます。

| 使いたいもの | 開く場所 | 主な用途 |
|-------------|----------|---------|
| 過去の会話 | 左サイドバーの会話一覧 | 続きの依頼を送る、会話を複製・共有する |
| AIへの依頼・進捗 | 中央のチャット | 指示、質問、承認、結果の確認 |
| 仕様書の閲覧 | 右パネル「設計」タブ | 仕様の検索・閲覧・レビュー |
| ソースコード・差分 | 右パネル「ファイル」タブ | ファイルの内容と変更差分の確認 |
| 変更の状態・記録 | 右パネル「履歴」タブ | 変更の反映、確定、過去の記録の確認 |
| ページのプレビュー | 右パネル「ブラウザ」タブ | 対応する実行環境での画面確認 |

<Note>
  右パネルが表示されていない場合は、画面右端の「右パネルを開く」をクリックします。画面幅や使用端末によって、パネルの配置や開き方が異なる場合があります。
</Note>

「設計」タブを使った仕様書の閲覧・レビュー、「履歴」タブの「反映」機能については、[仕様駆動開発のガイド](/guides/spec-driven-development)で詳しく説明しています。すべてのタブを毎回使う必要はなく、その時の作業内容に合わせて使い分けてください。

## 作業場所を決める三つの要素

AIが「どこで・何に対して」作業するかは、次の三要素で決まります。チャットを始める前にそれぞれを確認してください。

**サーバー**は、Speclane Studioの接続先です。ブラウザで開いているURLがサーバーを識別します。チームごと・プロジェクトごとに異なるサーバーが用意されている場合があります。

**ホスト**は、AIの作業を実際に実行するマシンです。自分のパソコンの場合も、チームで用意した別の環境（クラウド上の仮想マシンなど）の場合もあります。ホストのフォルダ構成は、ブラウザを開いているパソコンとは別である点に注意してください。

**作業ディレクトリ**は、AIが操作するフォルダです。右パネルの「ファイル」や「設計」に表示される内容も、この作業ディレクトリに対応します。プロジェクトのルートフォルダを指定するのが一般的です。

<Tabs>
  <Tab title="ローカルホストを使う場合">
    自分のパソコンでStudioサーバーとホストを起動しているケースです。ブラウザのURLは通常 `http://127.0.0.1:6767` になります。作業ディレクトリはローカルのプロジェクトフォルダを直接指定します。

    ```text
    サーバー  : http://127.0.0.1:6767
    ホスト    : localhost（自分のパソコン）
    作業ディレクトリ : /Users/yourname/projects/my-app
    ```
  </Tab>
  <Tab title="リモートホストを使う場合">
    管理者が用意したサーバーとリモートホストに接続するケースです。URLは管理者から案内されます。ホストに表示されるフォルダは、リモートマシン上のフォルダです。

    ```text
    サーバー  : https://studio.your-team.example.com
    ホスト    : dev-server-01（リモートマシン）
    作業ディレクトリ : /workspace/projects/my-app
    ```
  </Tab>
</Tabs>

<Note>
  ブラウザでチャットを開けている状態でも、**ホストがオフラインの場合はファイルの取得やAIの作業を継続できません**。ホストがオフラインと表示される場合は[接続の問題を確認する](/support/troubleshooting)を参照してください。
</Note>

## 既存のプロジェクトで作業を始める

オンラインのホストを選び、対象の作業ディレクトリを指定してチャットを開始します。初めてそのプロジェクトを扱う場合は、まずAIにプロジェクトの内容を説明させてから編集を依頼するとスムーズです。

```text
このプロジェクトの目的、主な機能、フォルダ構成を説明してください。
ファイルは変更しないでください。
```

「**リポジトリをコピー**」が表示される環境では、GitHubのリポジトリを選んでホスト上の作業ディレクトリへコピーできます。確認画面でコピー元・保存先・ブランチを確認してからコピーを実行してください。完了後にセッションが自動で始まり、入力済みの依頼が送られます。

## 同じフォルダで複数のAIが作業する場合

別のAIまたは別のチャットセッションが同じフォルダで作業していると、変更が重なる可能性があります。この状態では画面に警告が表示されます。

<AccordionGroup>
  <Accordion title="Gitワークツリーで作業を分ける">
    「詳細設定」内の「**Git ワークツリーブランチ（任意）**」に別ブランチ名を指定すると、同じリポジトリの異なるブランチを独立したフォルダとして扱えます。これにより、複数のセッションが互いに影響しない状態で並行作業できます。

    使用するブランチが決まっていない場合は、プロジェクト担当者に確認してください。
  </Accordion>
  <Accordion title="先の作業が終わるまで待つ">
    並行作業の必要がない場合は、実行中のセッションが完了してから次の依頼を送ります。競合リスクがなく、最もシンプルな方法です。
  </Accordion>
</AccordionGroup>
