Speclane Studioのメタハーネスとは、Claude Code・Codexをはじめとする複数のAIエージェントの実行方式を**共通の画面から統一的に操作するための基盤**です。どのAIを使う場合も、ホスト（実行マシン）と作業ディレクトリの選択、チャットによる依頼、結果の確認という操作フローは変わりません。Omnigentから引き継いだこの作業環境は、単発のコード修正や調査から、仕様を基準に据えた本格的な仕様駆動開発まで、あらゆる用途の共通基盤として機能します。

## メタハーネスとは何か

従来、AIコーディングエージェントはツールごとに専用のUIや設定が必要で、複数のエージェントを組み合わせる場合には都度切り替えが発生していました。Speclane Studioのメタハーネスは、その切り替えコストをなくすための仕組みです。

- **AIの違いをUIで吸収する** — エージェントごとの操作差異を共通インターフェースで統一します。
- **実行環境を明示的に管理する** — どのホストで・どのフォルダに対して作業するかを毎回明示するため、意図しない場所への変更を防ぎます。
- **会話を資産として扱う** — チャット履歴を複製・共有・インポートでき、チームで検討の続きを引き継げます。

## どんな目的で使えるか

| 用途 | 具体的な操作 |
|------|-------------|
| プロジェクトの調査 | AIにフォルダ構成・依存関係・主要ロジックを説明させる |
| コードの修正 | 変更箇所と完了条件を伝え、差分をファイルパネルで確認する |
| テストの依頼 | 失敗しているテストを指定し、修正と再実行を依頼する |
| 既存の検討の引き継ぎ | 別AIツールでの会話をインポートして続きを進める |
| 別案の試行 | 会話を複製して異なるアプローチを並行検討する |
| チームでの共同作業 | 会話を共有し、レビューや承認を複数人で行う |
| 仕様駆動開発の実施 | 仕様書を基準に実装依頼・検証・完了判断を一貫して行う |

仕様書やSpeclane-Skillsの準備は、メタハーネスを使い始めるための前提条件ではありません。まず基本操作に慣れてから、必要に応じて仕様駆動開発へ移行できます。

## 基本の進め方

<Steps>
  <Step title="作業環境を選ぶ">
    「エージェントを選択」で使用するAIを選び、「ホストを選択」で実行するマシンを指定し、「作業ディレクトリ」または「リポジトリ」で対象フォルダを確定します。

    ホストに表示されるフォルダは、そのホストに実際に存在するフォルダです。ブラウザを開いているパソコンのフォルダと同一とは限りません。
  </Step>
  <Step title="目的・対象・期待結果を伝える">
    チャット入力欄に「何をしたいか」「どのファイルを対象にするか」「どの状態になれば完了か」を明記して送信します。

    ```text
    src/components/Form.tsx の入力バリデーションを確認してください。
    まず現在のコードを読んで動作を説明し、ファイルは変更しないでください。
    ```
  </Step>
  <Step title="確認・承認に答える">
    AIから質問や承認を求める表示が出た場合は、内容を確認して判断を返します。不明な点があれば追加の質問を入力します。
  </Step>
  <Step title="結果を確かめる">
    AIの回答を読み、右パネルの「ファイル」タブで差分を確認します。テストが実行された場合はその結果も確認し、意図した変更になっているかを判断します。
  </Step>
  <Step title="次の依頼へ進む、または会話を管理する">
    問題なければ次の依頼を送ります。別案を試したい場合は会話を複製し、チームと共有したい場合は共有リンクを発行します。
  </Step>
</Steps>

## 仕様駆動開発との関係

仕様駆動開発においても、AIの選択・依頼・会話管理・結果確認という本ページで説明した操作はそのまま使います。仕様駆動開発が加えるのは、「何を仕様として合意するか」「何を実装の根拠にするか」「どの条件で完了を判断するか」という**判断基準の層**です。

<AccordionGroup>
  <Accordion title="仕様駆動開発が追加するステップ">
    基本の依頼フローに加えて、次のステップが入ります。

    1. **仕様の合意** — 実装前に、何を作るかの仕様をチームで確認します。
    2. **仕様書を参照した依頼** — 右パネル「設計」で仕様書を開きながら、その内容に沿った実装をAIに依頼します。
    3. **合意した条件に基づく検証** — 仕様に記載した完了条件をもとに、実装結果を検証します。
    4. **Speclane-Skillsの活用** — 定型的な作業を自動化・標準化するSkillsを組み合わせます。
  </Accordion>
  <Accordion title="仕様駆動開発を始めるには">
    まずこのページの基本操作に慣れてから、[仕様駆動開発のガイド](/guides/spec-driven-development)へ進んでください。Speclane-Skillsの準備が整っていなくても、仕様書を参照しながら依頼する形から始められます。
  </Accordion>
</AccordionGroup>

<Tip>
  最初の作業としては、プロジェクトの構成をAIに説明させることをおすすめします。ファイルを変更しない調査依頼でメタハーネスの操作フローを体験できます。[最初のチャットを始める](/start/quickstart)へ進んでください。
</Tip>
